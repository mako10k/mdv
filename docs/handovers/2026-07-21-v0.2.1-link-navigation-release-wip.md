## Important Review Finding And Fix

The initial dependency remediation was a false green: npm resolved DOMPurify 3.4.12 and `npm audit --omit=dev` returned zero, but Toast UI Editor 3.2.2's published ESM still embedded and executed DOMPurify 2.3.3. Consistency review found this only after the first expensive Windows candidate cycle.

The WIP fix is governed by ADR 0026:

- DOMPurify 3.4.12 is an exact direct dependency.
- A Vite pre-transform rebinds Toast UI's single internal sanitizer instance to that dependency.
- Toast UI is excluded from dependency pre-bundling so the transform always sees the upstream ESM.
- Upstream marker drift fails the build.
- `npm run build` checks the completed renderer entry for 3.4.12 and rejects the legacy 2.3.3 implementation.

The local Linux renderer bundle passes this contract. A final Windows `app.asar` has not yet been produced from it.

## Review-Timing Improvement

Use two review points instead of concentrating all judgment at the end:

1. Early contract review: after the smallest buildable implementation and before full regression / Windows packaging. It must trace the actual runtime or generated-artifact execution path, not only package metadata.
2. Final exact-diff review: after candidate evidence is complete, preserving the existing consistency, plain-eye, and packaging gates.

For dependency security changes, `npm audit` and lockfile versions are supporting evidence only. The early gate must prove which code the shipped bundle executes and add a fail-closed generated-output check before expensive release work begins.
